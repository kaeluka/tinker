# AGENTS.md — tinker project index

tinker is a goal-directed coding assistant: goals live as TOML files under `.tinker/goals/`, each one drives a per-goal agent session, and a TUI surfaces the live conversation alongside the goal tree. All agent-to-agent communication happens via `<@goal-id>…</@goal-id>` tag envelopes routed through the session registry.

---

## Core agents

These shared agents have no source-file mapping — they are the agents themselves, reachable via `<@id>…</@id>` from any goal session.

| agent | role |
|-------|------|
| `@tend` | Intent and *should*: holds the goal tree, answers what a goal means, conducts the interview, dispatches goal agents. Route intent questions and goal-content queries here. |
| `@rummage` | Precision backstop for code reality, technical validation, and counterexamples: every input is hypothesis material; execution is the only thing that closes a claim. Works the cycle Anchor → Hypothesize → Falsify → Integrate; falsification dispatched to a fresh sub-session. Scratch tests, fuzz harnesses, and instrumentation marked `tinker-test-case:`. Preauthorized to run code. Prefers whole-program runs with DI mocks over isolated modules; uses `lsp` for call-graph navigation, `webfetch`/`websearch` for external library detail. Never classifies intent-gap vs code-drift and never dispatches repairs — surfaces behavioral truth with precise locators to the triggering agent and to `@tend` when a goal claim is implicated. Output is hybrid: behavioral understanding (with execution citation) at the top, investigation logbook below; residual limits stated honestly. Route code-reality questions and spec↔code validation here. |
| `@jog` | Discrepancy finding: reads two redundant sources via read-only peer queries, runs forward coverage and backward provenance checks, and writes findings to `.tinker/discrepancies/`. Triggered unconditionally after each rummage dispatch. |

## Goal → source mapping

### tui
Terminal interface: two-column layout (conversation pane left; goal-list / goal-text / session-log stacked right), active-session switching, queue and trigger-reason display, scroll, mouse support, options dialog. Ephemeral sub-sessions appear in the goal list as soon as their opening `<@id|label>` tag is detected during streaming (not at turn completion). The goal-detail body normalizes every rendered line's list-item marker (`-`, `*`, `+`, or `1.`/`2)` style) to `-` so the marker is visually uniform regardless of what the goal author wrote.

- `src/repl_buffer.rs` — retained REPL buffer (`ReplBuffer`): incremental `Message`→`Line<'static>` conversion with per-message caching (`CachedEntry`), lazy recomputation of wrapped-line counts for the streaming last entry, and `viewport_lines()` culling so `draw_repl` never calls `Paragraph::line_count` on the full history. `build_message_lines()` is the single source of truth for message rendering (user/system/agent labels and styles). Includes spec tests for caching, idempotency, streaming updates, session-switch invalidation, and security edge cases (empty messages, zero width, very long text).
- `src/tui.rs` — all rendering: `pane_rects()` (layout geometry shared with mouse handler), `draw()`, `draw_repl()` (uses the retained `ReplBuffer` for incremental build and viewport culling; scroll state tracked via `ScrollState::cache_key`), `draw_goal_tree()` (goal-list rows rendered from `app.flat_items()`, indented via a `depth_by_id` map seeded from `flatten_tree()` for permanent goals then extended with ephemeral depths derived from `session_parent_id()`; label-first display: ephemeral rows show the dispatcher-provided label when present, falling back to the raw session ID; `session_base_id()` used to collapse fresh sub-session IDs to the root permanent goal name for the pane title and running markers), `goal_pane_title_line()` (styled pane title with `WERKELN_VERBS` cycling and running IDs rendered Yellow+Bold), `goal_detail_header_line()` (summary + `[kind · tier]` tag in muted gray, with italic for packaged goals), `normalize_list_marker()` (replaces any markdown list-item marker — unordered `-`/`*`/`+` or ordered `1.`/`2)`/`10.` — with `-`, preserving leading-space indent so nested items keep their nesting position; applied to every body line in the goal-text pane before the `Paragraph` is built; non-marker lines like prose, headings, and continuations pass through untouched), ephemeral detail pane (label-first line above the `↳ sub-session of {parent}` header; trigger-reason display when active), `draw_log()` (log pane works with any selected session — permanent or ephemeral — title uses the session ID directly), `draw_modal()` (options dialog: trigger-reason input and tier cycle selector with a session-reset warning), `goal_list_row_line()` (per-item row rendering with the packaged de-emphasis cascade: selection > packaged > active > default), `input_pane_layout()`, `render_log_line()`, `flatten_tree()` (depth-first traversal of the permanent goal tree, used internally to seed the depth map). The non-functional spec requires that REPL scroll behaviour remain smooth even when the conversation history grows large; this is delivered by `ReplBuffer`'s incremental cache and by avoiding full-buffer line-count recomputation every frame. Spec tests: `test_spec_normalize_list_marker_uses_dash_for_all_markers` (unordered, ordered, indented/nested, prose, headings, continuation, and empty lines); `test_spec_goal_detail_body_normalizes_list_markers_to_dash` (end-to-end body-line pipeline).

### goal-agents
Agent-architecture runtime: uniform per-goal session registry, `@goal-id` universal dispatch, framework preamble (VCS rules, `.tinker/` prohibition, implementation-ownership mandate, message-passing and neighbor-consultation sections), session init messages, startup-silence for `tend`, parse-correction loop.

- `src/goal_session.rs` — framework preamble constants (`VCS_RULES`, `TINKER_DIR_WRITE_RULES`, `IMPLEMENTATION_OWNERSHIP_MANDATE`, `MESSAGE_PASSING_AND_PROGRESS_SECTIONS`, `NEIGHBOR_CONSULTATION_MANDATE_PREAMBLE`, `FRESH_DISPATCH_INSTRUCTIONS`), `TRIGGER_REASON_MARKER` (sentinel `\x01` char prefixed to trigger-reason messages for TUI identification), `session_init_message()` (assembles the full system prompt — goal description + framework preamble + neighbors — delivered via the backend's native mechanism on the first turn), `build_neighborhood_table()`, `run_goal()`, `run_silent()`, `SessionEvent`; also `fresh_subsession_init_message()` and `fresh_subsession_lean_init_message()` (init builders for ephemeral sub-sessions). `MESSAGE_PASSING_AND_PROGRESS_SECTIONS` includes an "Acknowledgements close the exchange — no reply needed" instruction: receiving a pure acknowledgement means the exchange is complete; replying again invites a loop. Note: tier defaults are now kind-aware — behavior goals default to high tier, feature goals default to mid tier, and low tier is used only when explicitly set.
- `src/main.rs` — session registry (`running_sessions`, `SpawnGoalRequest`, `session_senders: Arc<Mutex<HashMap<String, mpsc::UnboundedSender<String>>>>` shared across goal-agent tasks so the `send_message` tool's dispatcher closures can reach the registry from any goal-agent task independent of main-loop borrow timing), `FreshSessionConfig` (ephemeral sub-session spawn config), `parse_fresh_dispatches()` (extracts `<@goal-id|label>…` envelopes), ephemeral-session spawn/retire logic in the main event loop (`ephemeral_sessions` tracking, `fresh_session_counter`), `dispatch_peer_consultations()` (tracks ALL dispatched recipients — including interactive agents tend/rummage/jog — in `running_sessions` so the batch-end retirement check waits for pending deliveries; delivery message uses plain text with a conditional reply prompt — "If you complete work based on this message: once you are done with this, reply via @{}" — rather than a bare `<@id>…</@id>` envelope, which would be re-parsed as a spurious dispatch), `handle_session_event()`, `tend_*` prompt builders, main event loop; goal agents and fresh sub-sessions both use `lean_init = true`: the per-call system prompt carries all session-invariant context, and the first turn is the trigger reason only (no `session_init_message` as user text), except tend which uses a full init message in the user turn

### peer-consult
Agent-to-agent @-block messaging channel: envelope detection in the finalized reply, tag-boundary and code-fence scoping, guaranteed delivery to recognized IDs, and the system message surfacing each exchange to the user. **Successor note:** `send-message` (below) is the structured-tool successor to the envelope path — both routes deposit into the same routing substrate and envelopes continue to work alongside until their eventual retirement; peer-consult owns the envelope side, send-message owns the tool side.

- `src/main.rs` — `parse_at_commands()` (extracts `<@id>…</@id>` envelopes from a finalized reply; code-fence and mid-line exclusion rules ensure only intentionally emitted envelopes are dispatched, not quoted or illustrative syntax); `dispatch_peer_consultations()` (routes non-fresh envelopes to each named session's input channel using plain-text delivery with a conditional reply prompt rather than a bare `<@id>` envelope, preventing re-parsing as a spurious dispatch; tracks all recipients in `running_sessions` so batch-end retirement waits for in-flight deliveries); `known_agent_ids()` (builds the routing table of recognized agent IDs from the current session registry)

### send-message
Structured-tool outbound dispatch available to every agent session: `send_message` takes `target` and `message` parameters, validates the target against the session registry, and delivers into the same routing substrate as @-block envelopes — but fires the recipient session immediately during the turn rather than at turn completion. Schema-enforced parameters remove the tag-format malformation failure mode of the envelope path; registry validation removes the silent-no-drop guarantee gap at the target-resolution layer. The tool routes only to already-registered sessions (fresh sub-sessions remain the @-envelope domain). Tool-delivered and envelope-delivered messages are indistinguishable to the recipient, and surface identical `→` lines in the conversation pane. The schema is intentionally mechanism-agnostic (only shape: two required string parameters) while the dispatch substrate is wired at the composition root — this keeps the tool stable across future protocol evolution while letting the registry-based implementation change independently in `src/main.rs`.

- `src/native.rs` — schema definition (`send_message`, description framing it as the preferred path over @-envelopes for registry-resident targets); `execute_send_message()` (validates `target` and `message` non-empty strings beyond the schema's shape validation; invokes the dispatcher closure the composition root supplied; returns the closure's `Ok`/`Err` unchanged); meta-tool status — when `name == "send_message"`, the tool loop bypasses `ToolPolicy` permission checks so every policy variant (including tend's restricted set) sees the tool, since the call touches no filesystem paths (registry validation happens inside the closure, not in the policy layer). `short_tool_summary()` maps `send_message` calls to a "target" one-liner. **12 `test_spec_` functions** cover: tool presence in function definitions for every policy variant, schema shape requirements, schema documentation of registry/in-turn semantics, short-summary mapping, successful callback delegation, surfaced callback error, no-callback defensive error, missing-target and missing-message validation, empty-target and empty-message rejection beyond schema, and tend's restricted tool list still containing `send_message`.
- `src/cap.rs` — `SendMessageFn` type alias (`Arc<dyn Fn(&str, &str) -> Result<String, String> + Send + Sync>` — `Arc` over `Box` so the same closure can be cloned cheaply across turns without re-wrapping); the 7th parameter on `OpenCodeRunner::run()` — an `Option<SendMessageFn>` dispatcher that the tool loop invokes on each `send_message` target/message pair. `None` makes the tool return a "no dispatcher configured" error (defensive — the composition root always supplies one in production, but the runner's trait contract does not require it). **Mock updates for callers of this new trait parameter:** `src/cleanup.rs` test runners pass `_send_message: None`; `src/goal_session.rs` test harnesses likewise — both sites compile against the new signature without exercising the trait.
- `src/main.rs` — `build_send_message_dispatcher(sender, session_senders, app, log)` (composition-root factory returning a per-sender closure); sender identity is captured inside the closure rather than carried as a trait parameter, keeping runners shareable across goal agents. Wraps the shared `session_senders: Arc<Mutex<HashMap>>` registry; emits a `SendMessageDispatched` log event on both success and unknown-target failure; formats the outgoing message through `prompts::delivery_message()` so recipients cannot distinguish tool delivery from envelope delivery. Called once per goal agent at startup (tend, each permanent goal, and each goal-agent loop). **6 `test_spec_` functions** cover: delivery to a known target, unknown-target error, no system message on failure, target marked running, delivery_message format, and a paired-event test that verifies success + failure both emit log events. `session_senders` was refactored from a bare `HashMap` in the main loop into an `Arc<Mutex<HashMap>>` shared across goal-agent tasks so sender closures can read/write the registry independent of main-loop borrow timing.
- `src/logger.rs` — `LogEvent::SendMessageDispatched { sender, target, success, error: Option<String> }` (serializes as `kind = "send_message_dispatched"`; carries sender/target as plain strings, success boolean, and failure reason when the target was not in the registry). Append-only — the variant does not mutate the UI state snapshot, so the TUI's `apply_to_state()` path ignores it. Exists separately from envelope-side dispatch events so introspection can distinguish the two delivery paths while acknowledging they share the same routing substrate. **2 `test_spec_` functions**: serialization shape and non-state-changing invariant.
- `prompts/goal_session/message_passing_and_progress.md` — "Preferred path: the `send_message` tool" subsection added under the message-passing instructions: schema-enforced parameters cannot be malformed the way an envelope can, fires in-turn rather than at end-of-turn, unknown targets return an explicit registry error so the sender can reroute.

### fresh-agents
Fresh-dispatch mechanism and global batch state: goal agents dispatch to ephemeral sub-sessions for tasks with inherent parallelism; each sub-session starts clean, may itself coordinate further sub-sessions (depth is unbounded), and remains inspectable until the next batch. This goal owns the batch state concept: the system is **active** whenever any work is in flight (a session is processing, a reply is being routed, or a user message is pending) and **idle** when nothing is outstanding; all completed ephemeral sub-sessions are retired at the idle→active transition that opens a new batch. Ephemeral sub-sessions appear in the TUI as soon as their opening tag is detected during streaming, not at turn completion.

- `src/goal_session.rs` — `FRESH_DISPATCH_INSTRUCTIONS` (protocol section injected into both regular goal-session init messages and fresh sub-session init messages, but excluded from the framework preamble constant; instructs agents to default to dispatching any decomposable sub-task to a fresh sub-session rather than doing it inline; includes an explicit prohibition on tool-level agent-spawning APIs such as the `Agent` tool — those calls bypass the harness entirely, making sub-sessions invisible to the goals pane and the event log and breaking batch accounting); `fresh_subsession_init_message()` and `fresh_subsession_lean_init_message()` (build the init for an ephemeral sub-session: ephemeral identity, parent-goal id, optional correlation label, task body, and `FRESH_DISPATCH_INSTRUCTIONS` so the sub-session can itself act as a coordinator and dispatch further sub-sessions)
- `src/main.rs` — `FreshSessionConfig` (carries `session_id`, `dispatcher_id`, `label`, neighbor list); `parse_fresh_dispatches()` (extracts complete `<@id|label>…</@id|label>` envelopes at Done time; **scoping rule**: only top-level envelopes count — envelopes inside fenced code blocks ` ``` `/`~~~` are ignored as illustrative, and envelopes that don't begin at the start of a trimmed line are treated as explanatory prose and skipped); `scan_opening_tags()` (detects opening `<@base_id|label>` tags during streaming without requiring a closing tag — used at Chunk time to pre-announce ephemeral sessions before the turn completes; applies the same code-fence and mid-line exclusion rules as `parse_fresh_dispatches()`); Chunk-time pre-announcement path in `handle_session_event()` (each new opening tag seen during streaming is pre-registered with a `~counter` ID into `running_sessions`, `ephemeral_sessions`, and `app.pending_fresh_announcements`); Done-time reconciliation path (matches complete envelopes to pre-announced IDs in order — reuses the pre-assigned ID so the TUI row never flickers; spawns a fresh ID for any envelope that arrived without a prior Chunk scan; silently removes pre-announced entries whose closing tag was never emitted); batch-start retirement at the **fresh-session spawn path**: fires only when all three conditions hold — (1) dispatcher is a permanent goal agent (not an ephemeral coordinator), (2) no ephemeral session is currently in `running_sessions`, (3) the dispatcher itself is not in `running_sessions` (no sub-session reply still in transit); retired IDs are removed from `session_senders`; `session_base_id()` resolves the permanent goal ID from an ephemeral coordinator dispatcher so init context and tier selection are always drawn from the root permanent goal

### backends
LLM backend abstraction via the native implementation — direct OpenRouter API calls with an in-process tool loop — delivered behind a trait seam for testability and composition honesty. File-access boundaries are enforced in code via the per-role `ToolPolicy` (not prompts). The former CLI backends (opencode, claude) are still present in source but slated for removal.

- `src/cap.rs` — `OpenCodeRunner` trait (including the `system_prompt: Option<&str>` parameter and the `send_message: Option<SendMessageFn>` parameter on `run()` — the dispatcher closure the tool loop invokes on each `send_message(target, message)` call; `None` makes the tool return a "no dispatcher configured" error), `Filesystem` trait, `Chunk` type alias, `SendMessageFn` type alias (`Arc<dyn Fn(&str, &str) -> Result<String, String> + Send + Sync>`)
- `src/native.rs` — `NativeRunner` (the designated sole backend); direct OpenRouter chat-completions calls (`reqwest`, key from `OPENROUTER_API_KEY`); in-process tool loop with seven tools (bash, read, write, edit, glob, grep, send_message); `ToolPolicy` enum (`Unrestricted` for goal sessions including cleanup, `TendScope` for tend — restricted tool set with a narrowed write scope on `.tinker/goals/`, denials returned to the model as tool errors; tend's schema list omits bash entirely, the `send_message` meta-tool is included in every policy because it does not touch the filesystem — registry validation happens in the dispatch callback the composition root supplies); `path_within()` performs permission checks with canonical-path resolution when possible (`fs::canonicalize` on existing targets, parent-directory canonicalization for new files) and a pure lexical fallback (`lexical_normalize()`) when the filesystem can't resolve; `extract_assistant_text()` handles both string and array content formats from the OpenAI spec; in-memory session store (`nat_<uuid>` ids; restart = fresh sessions); context overflow drops the session and returns `Err` so `goal_agent_loop` restarts fresh; model constants are OpenRouter ids (no `openrouter/` prefix). **Note:** this file also carries `tend-write-restriction`'s correctness property — equivalent filesystem paths produce the same permission outcome.
- `src/opencode.rs` — `RealOpenCodeRunner` (opencode backend, slated for removal); `create_agent_file_in_dir(agents_dir, system_prompt) -> (NamedTempFile, stem)` (`pub(crate)` helper); `opencode_command()`, `opencode_args()`; streaming JSON parser; `short_tool_summary()`
- `src/claude.rs` — `ClaudeRunner` (claude backend, slated for removal); `run()` resolves `effective_sp = system_prompt.or(self.system_prompt.as_deref())`; error-reinjection path; streaming JSON parser

### model-config
User-editable `.tinker/config.toml`: the goal targets three optional tier slots (high/mid/low) under a `[native]` section, absent slots fall back to built-in defaults; self-documenting starter template written only when no config file exists. **Source note:** `config.rs` still carries the full three-backend structure (`[claude]`, `[opencode]`, `[native]`, nine slots) — pending cleanup to match the goal.

- `src/config.rs` — `ModelConfig`, `BackendModelConfig`, `load_model_config()`, `write_starter_template()`

### tend-write-restriction
Correctness property of backends' `ToolPolicy` enforcement: the write-permission check must evaluate equivalent filesystem paths identically. An absolute path, a relative path with `..` components, and a symlink-resolved variant all referring to the same file must produce the same permission outcome.

- `src/native.rs` — `path_within()` (canonical-resolution permission check: `fs::canonicalize` on existing targets, parent-directory canonicalization for new files, pure `lexical_normalize()` fallback when the filesystem can't resolve)

### goal-storage
On-disk TOML format at `.tinker/goals/<id>.toml`: ancestor-directory merge (cwd-most wins on duplicate ids), malformed-file reporting without blocking siblings, transparent symlink following, `[[children]]` / `[[related]]` link shape.

- `src/goal.rs` — `Goal` (fields include `kind: Option<String>` — `"feature"` or `"behavior"`, optional on legacy goals), `RelatedLink`, `ChildLink`, `GoalNode`; `GOAL_SCHEMA_KEYS_ORDER` (single source of truth for schema key order used in prompts and parse-error correction); `discover_tinker_dirs()`, `load_all_goals()`, `load_goals()`, `save_goal()`, `build_tree()`, `build_compact_index()` (emits `kind` in each compact index entry), `build_full_text_index()`

### tier-edit

Tier defaults are now kind-aware: behavior goals default to high tier, feature goals default to mid tier, and low tier is used only when explicitly set.
TUI tier-change interaction: `t` on a focused goal cycles its tier (absent/mid → high → low → absent/mid) and writes the updated `tier` field immediately to the goal's source TOML file; the goal-detail header's `[kind · tier]` tag reflects the new value at once.

- `src/main.rs` — `effective_goal_tier()` (single source of truth for kind-aware tier resolution: explicit tier wins, absent tier: behavior→high, feature/unknown→mid), `cycle_tier()` (three-value cycle logic), `KeyAction::CycleTier(goal_id)` variant, key-event dispatch (`t` in the goal-tree returns `CycleTier` for any goal with a `source_path`), and the `CycleTier` event-loop handler that mutates `app.goals` in-place, serializes via `toml::to_string_pretty()`, and writes via `fs.write()`

### packaged-goals-style
Visual de-emphasis rule for packaged goals: they render grey and italic in the goal-list rows and detail-pane header to signal that they are tinker's internal machinery, not the user's stated intent.

- No dedicated source file — rendering rule consumed by `tui`'s goal-list and detail-pane drawing code in `src/tui.rs`.

### goal-placement
Placement reviewer: when tend creates or edits a goal, checks that it lives in the directory matching its scope — packaged (`~/.tinker/goals/`) for content valid across any tinker project, project-local (`.tinker/goals/`) for content specific to this project — and flags drift when edits make a packaged goal project-specific.

- No dedicated source file — pure behavior goal enforced through tend's session prompting at write time.

### cleanup-hook
Pre-session cleanup: scans the project tree for `tinker-test-case:` markers left by rummage, dispatches a cheap agent to remove each one, retries up to 3 times, blocks the session if any marker survives.

- `src/cleanup.rs` — `run_cleanup()`, `find_marker_files()`, `build_cleanup_prompt()`, `file_contains_marker()`; `MARKER` constant, `CleanupOutcome`, `MAX_RETRIES`

### coding-standards
Post-batch code quality enforcement: runs when a batch produces source-code changes, addressing compiler warnings and linter findings, checking conformance to standing standards (capability-based DI, polymorphism ladder, tests-as-guardrails, security.md, tinkerability), and auditing spec-test coverage in both directions. Compiler warnings are fixed, not suppressed — unused functions, dead imports, and unreachable code are removed; suppression requires a justified reason explaining why the warning is acceptable, not just "intentional".

- No dedicated source file — pure behavior goal enforced through the goal session's standing-constraint prompting.

### tend-introspection
Runtime introspection substrate: append-only event log at `.tinker/logs/runtime.jsonl` capturing turns, goal-session lifecycle, `@`-dispatch, cleanup, goal-file changes, TUI state, and batch state transitions (idle→active and active→idle) as first-class events; batch transitions also emit as user-visible system messages; semantic state snapshot at `.tinker/state/runtime.json` written async and non-blocking.

- `src/logger.rs` — `LogSender`, `start_logger()`, `LogEvent` (all event variants, including `SendMessageDispatched { sender, target, success, error: Option<String> }` — emitted on every `send_message` tool call to distinguish tool-delivered dispatches from envelope-delivered ones while acknowledging they share the same routing substrate), `StateSnapshot`, `QueueEntry`, `ScrollOffsets`, `apply_to_state()`, `hash_string()`, `count_tool_calls()`, `extract_modified_files()`

### startup-args
CLI argument handling: validates incoming args against the recognised flag set, unknown-argument error path (print help + exit 1), `--help`/`-h` handler, help text content. The goal recognises only `--tend-full-goal-context` (plus `--help`/`-h`); **source note:** `main.rs` still handles `--claude`, `--native`, `--default-model`, and their mutual-exclusion checks — pending cleanup to match the goal.

- `src/main.rs` — `print_help()` and the argument parsing block in `main()`

### prompt-storage
File-based prompt storage: all LLM-facing prompt strings extracted from inline source literals into the `prompts/` directory, embedded at compile time via `include_str!` and filled by `src/prompts.rs`. Consumed by `goal-agents` (session init templates, framework preamble constants, delivery messages, silence nudges, parse-correction prompts), `backends` (shared tool/stream formatting templates — `→`/`⚠` lines — the native backend renders chunks with; **note:** CLI error reinjection templates `process_error.md` and `stderr_prefix.md` still exist, pending removal with the CLI backends), and `cleanup-hook` (cleanup agent prompt).

- `src/prompts.rs` — prompt loading and templating module (`include_str!`s each file under `prompts/` and interpolates `{PLACEHOLDER}` variables via `str::replace`)
- `prompts/` directory — extracted prompt files grouped by consumer module (`goal_session/`, `backends/`, `main/`, `cleanup/`, `config/`), plain text with `{PLACEHOLDER}` interpolation syntax

## Shared infrastructure (no dedicated goal)

- `src/app.rs` — `GoalListItem` enum (`Goal(Goal)` | `Ephemeral(String, Option<String>)`) representing a single row in the goal list (the optional label enables label-first display in `tui`'s row rendering); `session_base_id(id)` (strips all `~{counter}` suffixes, returning the root permanent goal ID — used for pane-label normalization and running-marker lookup); `session_parent_id(id)` (strips only the trailing `~{counter}` segment, returning the immediate parent — used for nesting ephemeral rows); `flat_items()` (builds the depth-first ordered list of `GoalListItem` values with each ephemeral inserted immediately after its immediate parent, supporting unbounded nesting depth; labels resolved from `ephemeral_labels`); `App` (central mutable state shared by TUI and event loop; includes `ephemeral_sessions: HashSet<String>`, `ephemeral_sessions_ordered: Vec<String>`, `ephemeral_labels: HashMap<String, Option<String>>`, `fresh_session_counter: u64`, and `pending_fresh_announcements: HashMap<String, Vec<(String, Option<String>)>>` — a map from base goal ID to pre-announced ephemeral sessions detected during streaming before their turn completes), `Message`, `Role`, `Focus`, `Phase`, `ModalState`, `ScrollState`

- `src/test_utils.rs` — `MockFilesystem` and helpers used by unit tests
