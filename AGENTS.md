# AGENTS.md — tinker project index

tinker is a goal-directed coding assistant: goals live as TOML files under `.tinker/goals/`, each one drives a per-goal agent session, and a TUI surfaces the live conversation alongside the goal tree. Agent-to-agent communication uses the `send_message` tool (schema-enforced, fires in-turn, fails outright on unknown targets). Fresh sub-sessions are spawned via the `spawn_session` tool (self-only routing, fires in-turn).

---

## Core agents

These shared agents have no source-file mapping — they are the agents themselves, reachable via `send_message` from any goal session.

| agent | role |
|-------|------|
| `tend` | Intent and *should*: holds the goal tree, answers what a goal means, conducts the interview, dispatches goal agents. Route intent questions and goal-content queries here. |
| `rummage` | Precision backstop for code reality, technical validation, and counterexamples: every input is hypothesis material; execution is the only thing that closes a claim. Works the cycle Anchor → Hypothesize → Falsify → Integrate; falsification dispatched to a fresh sub-session. Scratch tests, fuzz harnesses, and instrumentation marked `tinker-test-case:`. Preauthorized to run code. Prefers whole-program runs with DI mocks over isolated modules; uses `lsp` for call-graph navigation, `webfetch`/`websearch` for external library detail. Never classifies intent-gap vs code-drift and never dispatches repairs — surfaces behavioral truth with precise locators to the triggering agent and to `tend` when a goal claim is implicated. Output is hybrid: behavioral understanding (with execution citation) at the top, investigation logbook below; residual limits stated honestly. Route code-reality questions and spec↔code validation here. |
| `jog` | Discrepancy finding: reads two redundant sources via read-only `send_message` queries, runs forward coverage and backward provenance checks, and writes findings to `.tinker/discrepancies/`. Triggered unconditionally after each rummage dispatch. |

## Goal → source mapping

### tui
Terminal interface: two-column layout (conversation pane left; goal-list / goal-text / session-log stacked right), active-session switching, queue and trigger-reason display, scroll, mouse support, options dialog. Ephemeral sub-sessions appear in the goal list as soon as the `spawn_session` tool fires during the dispatcher's turn (in-turn, not at turn completion). The goal-detail body normalizes every rendered line's list-item marker (`-`, `*`, `+`, or `1.`/`2)` style) to `-` so the marker is visually uniform regardless of what the goal author wrote.

- `src/repl_buffer.rs` — retained REPL buffer (`ReplBuffer`): incremental `Message`→`Line<'static>` conversion with per-message caching (`CachedEntry`), lazy recomputation of wrapped-line counts for the streaming last entry, and `viewport_lines()` culling so `draw_repl` never calls `Paragraph::line_count` on the full history. `build_message_lines()` is the single source of truth for message rendering (user/system/agent labels and styles). Includes spec tests for caching, idempotency, streaming updates, session-switch invalidation, and security edge cases (empty messages, zero width, very long text).
- `src/tui.rs` — all rendering: `pane_rects()` (layout geometry shared with mouse handler), `draw()`, `draw_repl()` (uses the retained `ReplBuffer` for incremental build and viewport culling; scroll state tracked via `ScrollState::cache_key`), `draw_goal_tree()` (goal-list rows rendered from `app.flat_items()`, indented via a `depth_by_id` map seeded from `flatten_tree()` for permanent goals then extended with ephemeral depths derived from `session_parent_id()`; label-first display: ephemeral rows show the dispatcher-provided label when present, falling back to the raw session ID; `session_base_id()` used to collapse fresh sub-session IDs to the root permanent goal name for the pane title and running markers), `goal_pane_title_line()` (styled pane title with `WERKELN_VERBS` cycling and running IDs rendered Yellow+Bold), `goal_detail_header_line()` (summary + `[kind · tier]` tag in muted gray, with italic for packaged goals), `normalize_list_marker()` (replaces any markdown list-item marker — unordered `-`/`*`/`+` or ordered `1.`/`2)`/`10.` — with `-`, preserving leading-space indent so nested items keep their nesting position; applied to every body line in the goal-text pane before the `Paragraph` is built; non-marker lines like prose, headings, and continuations pass through untouched), ephemeral detail pane (label-first line above the `↳ sub-session of {parent}` header; trigger-reason display when active), `draw_log()` (log pane works with any selected session — permanent or ephemeral — title uses the session ID directly), `draw_modal()` (options dialog: trigger-reason input and tier cycle selector with a session-reset warning), `goal_list_row_line()` (per-item row rendering: idle prefix `-`, active prefix `▶`, both always dim (DarkGray) regardless of row state — the marker recedes against the goal name; packaged de-emphasis cascade for id and summary styles: selection > packaged > active > default), `input_pane_layout()`, `render_log_line()`, `flatten_tree()` (depth-first traversal of the permanent goal tree, used internally to seed the depth map). The non-functional spec requires that REPL scroll behaviour remain smooth even when the conversation history grows large; this is delivered by `ReplBuffer`'s incremental cache and by avoiding full-buffer line-count recomputation every frame. Spec tests: `test_spec_idle_marker_is_dash` (idle rows open with dash, not a heavy bullet); `test_spec_marker_is_dim_and_unitalic_on_packaged_row` (prefix stays DarkGray even on packaged rows — the grey+italic rule covers id and summary only); `test_spec_ephemeral_idle_marker_is_dash_and_dim` (ephemeral rows follow the same rule); `test_spec_goal_list_row_packaged_non_selected_uses_grey_and_italic` (packaged cascade); `test_spec_goal_list_row_selected_packaged_uses_selection_color_with_italic_id`; `test_spec_goal_list_row_project_local_does_not_get_italic`; `test_spec_goal_detail_header_packaged_uses_italic`; `test_spec_normalize_list_marker_uses_dash_for_all_markers` (unordered, ordered, indented/nested, prose, headings, continuation, and empty lines); `test_spec_goal_detail_body_renders_list_items_with_dash` (end-to-end body-line pipeline).

### goal-agents
Agent-architecture runtime: uniform per-goal session registry, `send_message` universal dispatch, framework preamble (VCS rules, `.tinker/` prohibition, implementation-ownership mandate, message-passing and neighbor-consultation sections), session init messages, startup-silence for `tend`, parse-correction loop.

Note: tier defaults are now kind-aware — behavior goals default to high tier, feature goals default to mid tier, and low tier is used only when explicitly set.
- `src/main.rs` — session registry (`running_sessions`, `SpawnGoalRequest`, `session_senders: Arc<Mutex<HashMap<String, mpsc::UnboundedSender<String>>>>` shared across goal-agent tasks so the `send_message` tool's dispatcher closures can reach the registry from any goal-agent task independent of main-loop borrow timing), `FreshSessionConfig` (ephemeral sub-session spawn config), ephemeral-session spawn/retire logic in the main event loop (`ephemeral_sessions` tracking, `fresh_session_counter`), `handle_session_event()`, `tend_*` prompt builders, main event loop; goal agents and fresh sub-sessions both use `lean_init = true`: the per-call system prompt carries all session-invariant context, and the first turn is the trigger reason only (no `session_init_message` as user text), except tend which uses a full init message in the user turn. **Eager-start diagnostic** (right after the initial `load_all_goals`): the `expect("tend goal not found…")` guarding `tend_description` is the loud surface for the eager-start invariant — when tend is missing from the merged result, the panic names the four-tier loader (project-local → ancestor global → tinker_dir-packaged → binary-relative-packaged) and points at `cargo build` / reinstall as fixes. Diagnostic text content is owned by `binary-relative-tier-loading`; the check-exists invariant is `goal-agents`'s.

### send-message
Structured-tool outbound dispatch available to every agent session: `send_message` takes `target` and `message` parameters, validates the target against both the session registry and the goal tree, and delivers into the routing substrate — firing the recipient session immediately during the turn rather than at turn completion. Schema-enforced parameters remove the tag-format malformation failure mode of free-form text dispatch; registry-then-goal-tree validation means a known goal is lazy-spawned on first contact (via `SpawnGoalRequest`) so the tool succeeds for any recognized goal whether or not it has a running session yet. The tool fails outright on truly unknown targets — not in the registry and not in the goal tree — and on self-send (target equal to the caller's session id, which would create a new turn in the same session and recurse without bound). Fresh sub-sessions are the `spawn_session` domain. Tool-delivered messages surface a `→` line in the conversation pane. The schema is intentionally mechanism-agnostic (only shape: two required string parameters) while the dispatch substrate is wired at the composition root — this keeps the tool stable across future protocol evolution while letting the registry-based implementation change independently in `src/main.rs`.

- `src/native.rs` — schema definition (`send_message`, description framed to reflect the registry-or-lazy-spawn behavior — the target is validated against both the session registry and the goal tree, and a known-but-unspawned goal is lazy-spawned so the message is delivered into the new session; explicitly directing callers to `spawn_session` for fresh sub-sessions of their own goal; explicitly calling out the self-send rejection — passing the sender's own id as the target returns an error to prevent unbounded recursion; schema-level property description on `target` reinforces the same registry-or-lazy-spawn framing and the self-send constraint); `execute_send_message()` (validates `target` and `message` non-empty strings beyond the schema's shape validation; invokes the dispatcher closure the composition root supplied; returns the closure's `Ok`/`Err` unchanged); meta-tool status — when `name == "send_message"`, the tool loop bypasses `ToolPolicy` permission checks so every policy variant (including tend's restricted set) sees the tool, since the call touches no filesystem paths (registry and goal-tree validation happens inside the closure, not in the policy layer). `short_tool_summary()` maps `send_message` calls to a "target" one-liner. `format_tool_error` for the self-send case builds a `⚠ send_message <target>: ...` line that surfaces the self-send condition, the offending target id, and the alternatives-aware course-correction pointers (the dispatcher error is single-line, so the full string flows through `first_line` into the streamed chunk — both the user reading the conversation pane and the model reading the tool result see the same content). **14 `test_spec_` functions** cover: tool presence in function definitions for every policy variant, schema shape requirements, schema documentation of registry/in-turn semantics, schema documentation of registry-or-lazy-spawn (both descriptions must mention session registry + goal tree + lazy-spawn + the "unknown" error framing, and must NOT contain the misleading "must already exist in the session registry" wording), short-summary mapping, successful callback delegation, surfaced callback error, no-callback defensive error, missing-target and missing-message validation, empty-target and empty-message rejection beyond schema, tend's restricted tool list still containing `send_message`, and the self-send warning-line surface (`format_tool_error` output for a self-send Err must contain the tool name, target summary, self-send condition, target id, and all three course-correction pointers).
- `src/cap.rs` — `SendMessageFn` type alias (`Arc<dyn Fn(&str, &str) -> Result<String, String> + Send + Sync>` — `Arc` over `Box` so the same closure can be cloned cheaply across turns without re-wrapping); the 7th parameter on `OpenCodeRunner::run()` — an `Option<SendMessageFn>` dispatcher that the tool loop invokes on each `send_message` target/message pair. `None` makes the tool return a "no dispatcher configured" error (defensive — the composition root always supplies one in production, but the runner's trait contract does not require it). **Mock updates for callers of this new trait parameter:** `src/cleanup.rs` test runners pass `_send_message: None`; `src/goal_session.rs` test harnesses likewise — both sites compile against the new signature without exercising the trait.
- `src/main.rs` — `RouteOutcome` enum (`Delivered`, `ChannelClosed`, `LazySpawned`, `Unknown` — the result type for the registry-then-lazy-spawn decision, produced inline by `build_send_message_dispatcher`); `build_send_message_dispatcher(sender, session_senders, goal_spawn_tx, app, log)` (composition-root factory returning a per-sender closure; takes the `goal_spawn_tx` channel so the closure can lazy-spawn known-but-unspawned goals; takes the senders lock briefly, drops it, then takes the app lock to consult the goal tree — never holds both at once). The closure uses `RouteOutcome` to handle all four cases: success (Delivered or LazySpawned — same system message, running_sessions tracking, and log event), channel-closed (lost-delivery warning), unknown (error returned to the model), and **self-send** (target equal to the caller's session id — returned as `Err` with an alternatives-aware course-correction message *before* any state mutation, so a rejected self-send has no system message, no `running_sessions` entry, and no successful-delivery log event; the error string names the offending target and points to the three specific alternatives — `spawn_session` for sub-tasks of self, a different goal id for a different agent, or continue reasoning — closing the loop faster than a generic "pick a different target" hint because send_message and spawn_session are sibling tools with different semantics; a `SendMessageDispatched { success: false }` event is emitted for introspection symmetry). For the LazySpawned case, the target is inserted into `running_sessions` before the `SpawnGoalRequest` drains, which is the gap the batch-end retirement check must wait through. Emits a `SendMessageDispatched` log event on each outcome. Called once per goal agent at startup (tend, each permanent goal, and each goal-agent loop). **10 `test_spec_` functions** cover: delivery to a known target, unknown-target error, no system message on failure, target marked running, delivery_message format, paired-event test for success + failure log events, lazy-spawn for a known-but-unspawned goal, lazy-spawn tracking in `running_sessions` before the spawn drains, self-send rejection (no side effects, no delivery, no system message), self-send error message names the three alternatives (`spawn_session` pointer, different goal id pointer, continue-reasoning fallback), and known-peer / unknown-target regression checks that the self-send guard does not weaken existing behavior. `session_senders` is an `Arc<Mutex<HashMap>>` shared across goal-agent tasks so sender closures can read/write the registry independent of main-loop borrow timing.
- `src/logger.rs` — `LogEvent::SendMessageDispatched { sender, target, success, error: Option<String> }` (serializes as `kind = "send_message_dispatched"`; carries sender/target as plain strings, success boolean, and failure reason when the target was not in the registry; the self-send failure case is a first-class observable — `target == sender` is the structural signal a consumer can filter on without grepping the error string, and the error string round-trips verbatim with the alternatives-aware course-correction content). Append-only — the variant does not mutate the UI state snapshot, so the TUI's `apply_to_state()` path ignores it. **3 `test_spec_` functions**: serialization shape (success + failure paths), non-state-changing invariant, and self-send round-trip (`target == sender` plus the full alternatives-aware error string preserved verbatim).
- `prompts/goal_session/message_passing_and_progress.md` — message-passing instructions delivered via the `send_message` tool: schema-enforced parameters, fires in-turn, unknown targets return an explicit registry error so the sender can reroute.

### spawn-session
Tool-call harness surface for spawning fresh sub-sessions: the `spawn-session` tool takes `subgoal` (self-contained task description) and an optional `label` (short correlation tag), spawning a fresh ephemeral sub-session of the caller's own goal immediately during the caller's turn. Schema-enforced parameters remove the format-fragility failure mode of free-form text dispatch; spawned sub-sessions appear in the session registry, participate in batch accounting, and render identically to any other session. Sibling tool to `send-message` on the shared dispatch substrate — the domain split is target semantics: `send-message` targets existing registry entries or lazy-spawns permanent goals; `spawn-session` targets only the caller's own goal for fresh ephemeral sub-sessions.

- `src/native.rs` — schema definition (`spawn_session`: required `subgoal` (string), optional `label` (string); description frames it as self-only (no `target` parameter — routing target implicit in caller) and firing in-turn); `execute_spawn_session()` (validates `subgoal` non-empty, normalises `label` — absent/null/empty-string all map to `None` — delegates to the dispatcher callback, surfaces callback errors and the "no dispatcher configured" error); meta-tool status — when `name == "spawn_session"`, the tool loop bypasses `ToolPolicy` permission checks (the tool touches no filesystem paths; self-only routing is enforced in the callback, not the policy layer); `short_tool_summary()` maps `spawn_session` calls to the label when present, falling back to the first line of the subgoal. **11 `test_spec_` functions** cover: tool presence in function definitions for every policy variant, schema shape (required params), schema documentation of self-only and in-turn semantics, short-summary label preference (with/without/empty label), dispatcher callback delegation, no-label delegation, surfaced callback error, no-callback defensive error, missing-subgoal error, empty-subgoal rejection, and empty-label normalisation to `None`.
- `src/cap.rs` — `SpawnSessionFn` type alias (`Arc<dyn Fn(&str, Option<&str>) -> Result<(String, Option<String>), String> + Send + Sync>`); return tuple carries `(session_id, label)` so the caller can see both the new sub-session's id and the preserved correlation tag. Signature mirrors `SendMessageFn` in shape (Arc over Box for cheap cross-turn cloning, `Send + Sync`).
- `src/main.rs` — `build_spawn_session_dispatcher(caller_session_id, goal_spawn_tx, app, log)` (composition-root factory returning a per-caller closure; captures the caller's full session id — permanent or ephemeral coordinator — as the new sub-session's id prefix so TUI nesting mirrors the immediate-dispatcher relationship; looks up the caller's permanent base goal via `app::session_base_id()` to build the sub-session's init context; on missing goal returns `Err` and undoes registry bookkeeping; on success: pre-assigns `{caller}~{counter}` id, updates `running_sessions`/`ephemeral_sessions`/`ephemeral_labels`, enqueues a `SpawnGoalRequest` with `fresh_session: Some(...)`, emits a system message and a `SpawnSessionDispatched` log event, returns `(session_id, label)`). The closure uses `SpawnGoalRequest` — same channel as the send-message lazy-spawn path — so the two tools share the init/spawn plumbing. **6 `test_spec_` functions** cover: successful spawn request enqueue for a known goal, coordinator-nesting (id prefix is the caller's full session id, not the permanent base), system-message emission on success, unknown-caller-goal error path, monotonic counter increment, and `goal_id` field being the permanent base (not the ephemeral caller id). `cleanup.rs` and `goal_session.rs` test harnesses accept the new trait parameter (`_spawn_session: Option<crate::cap::SpawnSessionFn>`) without exercising it.
- `src/logger.rs` — `LogEvent::SpawnSessionDispatched { sender, sub_session_id, label: Option<String>, success, error: Option<String> }` (serializes as `kind = "spawn_session_dispatched"`; `sender` may be a permanent goal ID or an ephemeral coordinator ID; `sub_session_id` is the new `~{counter}` id; `label` is `Some(tag)` or `None`). Exists separately from `SendMessageDispatched` so introspection can distinguish fresh-sub-session spawns from permanent-target dispatches. Append-only — does not mutate the UI state snapshot.
- `prompts/goal_session/fresh_dispatch.md` — primary prompt section for `spawn_session`: tool schema (subgoal required, label optional), self-only routing note ("schema exposes no target parameter — the new sub-session is always of *your own goal*"), in-turn dispatch, coordinator role, and an explicit prohibition on LLM-backend spawn APIs (e.g. an `Agent` tool).
- `prompts/goal_session/message_passing_and_progress.md` — cross-reference to `spawn_session` in the sub-session spawning subsection with the same tool call example; the "Spawning fresh sub-sessions" section instructs sub-sessions to dispatch further sub-sessions via `spawn_session`.

### fresh-agents
Fresh-dispatch mechanism and global batch state: goal agents dispatch to ephemeral sub-sessions for tasks with inherent parallelism; each sub-session starts clean, may itself coordinate further sub-sessions (depth is unbounded), and remains inspectable until the next batch. This goal owns the batch state concept: the system is **active** whenever any work is in flight (a session is processing, a reply is being routed, or a user message is pending) and **idle** when nothing is outstanding; all completed ephemeral sub-sessions are retired at the idle→active transition that opens a new batch. Dispatch goes through the `spawn_session` tool — the sole sub-session spawning surface, firing in-turn at the tool call.

- `src/goal_session.rs` — `FRESH_DISPATCH_INSTRUCTIONS` (protocol section injected into both regular goal-session init messages and fresh sub-session init messages, but excluded from the framework preamble constant; instructs agents to default to dispatching any decomposable sub-task to a fresh sub-session rather than doing it inline; makes the `spawn_session` tool the sole dispatch surface; includes an explicit prohibition on tool-level agent-spawning APIs such as the `Agent` tool — those calls bypass the harness entirely, making sub-sessions invisible to the goals pane and the event log and breaking batch accounting); `fresh_subsession_init_message()` and `fresh_subsession_lean_init_message()` (build the init for an ephemeral sub-session: ephemeral identity, parent-goal id, optional correlation label, task body, and `FRESH_DISPATCH_INSTRUCTIONS` so the sub-session can itself act as a coordinator and dispatch further sub-sessions)
- `prompts/goal_session/fresh_dispatch.md` — primary prompt section for `spawn_session`: tool call example, self-contained subgoal requirement, optional label, in-turn dispatch, coordinator role, self-only routing note ("schema exposes no target parameter"), and explicit prohibition of LLM-backend spawn APIs
- `prompts/goal_session/message_passing_and_progress.md` — cross-reference to `spawn_session` in the sub-session spawning subsection with the same tool call example
- `src/main.rs` — `FreshSessionConfig` (carries `session_id`, `dispatcher_id`, `label`, neighbor list); batch-start retirement at the **fresh-session spawn path**: fires only when all three conditions hold — (1) dispatcher is a permanent goal agent (not an ephemeral coordinator), (2) no ephemeral session is currently in `running_sessions`, (3) the dispatcher itself is not in `running_sessions` (no sub-session reply still in transit); retired IDs are removed from `session_senders`; `session_base_id()` resolves the permanent goal ID from an ephemeral coordinator dispatcher so init context and tier selection are always drawn from the root permanent goal

### recursive-subdivision
Behavior goal for recursive problem decomposition: when a problem's structure demands decomposition at multiple levels and branches, this agent receives the problem and spawns sub-agents via `spawn_session` at whatever depth the structure requires. It is a purpose-built consumer of the `fresh-agents` ephemeral sub-session mechanism and the `spawn-session` tool surface — designed as a design study for large, autonomous plans that need unbounded recursive subdivision.

- No dedicated source file — pure behavior goal; runs within the agent-session framework using `spawn_session` (the tool surface `spawn-session` provides) to create its sub-agents, exercising the full depth `fresh-agents` supports.

### backends
LLM backend abstraction via the native implementation — a single `NativeRunner` that talks to any OpenAI-protocol chat-completions endpoint, run as an in-process tool loop behind a trait seam for testability and composition honesty. The endpoint, model, and per-instance auth are **per-`NativeRunner`-instance** (not module-level constants) so the composition root can wire different combinations per tier — e.g. OpenRouter for one tier, a local model server (no `Authorization` header) for another. File-access boundaries are enforced in code via the per-role `ToolPolicy` (not prompts). The former CLI backends (`opencode`, `claude`) have been removed; `NativeRunner` is the sole backend.

- `src/cap.rs` — `OpenCodeRunner` trait (including the `system_prompt: Option<&str>` parameter and the `send_message: Option<SendMessageFn>` parameter on `run()` — the dispatcher closure the tool loop invokes on each `send_message(target, message)` call; `None` makes the tool return a "no dispatcher configured" error), `Filesystem` trait, `Chunk` type alias, `SendMessageFn` type alias (`Arc<dyn Fn(&str, &str) -> Result<String, String> + Send + Sync>`)
- `src/native.rs` — `NativeRunner` (the sole backend): per-instance `endpoint: String`, `model: String`, and `api_key: Option<String>` (the struct fields take the place of the previous module-level `OPENROUTER_*` constants — `None` means no `Authorization` header is sent, the local-model-server path); constructors `NativeRunner::new(endpoint, model, api_key, policy)` and `NativeRunner::with_system_prompt(...)` for tend's struct-level scope framing; in-process tool loop with the filesystem tools (read, write, edit, delete, glob, grep) plus `bash`, and the meta-tools `send_message` and `spawn_session`; `delete` handles both files and directories (recursive for directories) and is subject to the same `ToolPolicy` scope check as write/edit — tend may only delete under `.tinker/goals/`; `ToolPolicy` enum (`Unrestricted` for goal sessions including cleanup, `TendScope` for tend — restricted tool set with a narrowed write scope on `.tinker/goals/`, denials returned to the model as tool errors; tend's schema list omits bash entirely, the `send_message`/`spawn_session` meta-tools are included in every policy because they do not touch the filesystem — registry and self-only routing validation happen in the dispatch callbacks the composition root supplies); `path_within()` performs permission checks with canonical-path resolution when possible (`fs::canonicalize` on existing targets, parent-directory canonicalization for new files) and a pure lexical fallback (`lexical_normalize()`) when the filesystem can't resolve; `extract_assistant_text()` handles both string and array content formats from the OpenAI spec; in-memory session store (`nat_<uuid>` ids; restart = fresh sessions); context overflow drops the session and returns `Err` so `goal_agent_loop` restarts fresh; bearer-auth header added only when `api_key` is `Some` — the request body is otherwise identical regardless of provider. **Note:** this file also carries `tend-write-restriction`'s correctness property — equivalent filesystem paths produce the same permission outcome.

### model-config
User-editable `.tinker/config.toml`: per-tier blocks (`[native.high]`, `[native.mid]`, `[native.low]`), each carrying `endpoint` (an OpenAI-protocol chat-completions URL) and `model` (a model identifier the endpoint serves). Either field may be absent independently; absent fields fall back to the loader's built-in defaults (OpenRouter endpoints + OpenRouter model ids, used as a sensible default that any OpenAI-protocol endpoint can also satisfy). **Auth is sourced from per-tier environment variables** — `TINKER_HIGH_API_KEY`, `TINKER_MID_API_KEY`, `TINKER_LOW_API_KEY` — never stored in the TOML. Empty/unset env vars resolve to `None` (no `Authorization` header sent), which is what local model servers expect. The self-documenting starter template is written only when no config file exists; it documents all three per-tier env vars and the per-tier consumer agents (high → tend/rummage/jog; mid → goal sessions; low → cleanup).

- `src/config.rs` — `ModelConfig` (top-level TOML shape — `native: Option<NativeModelConfig>`); `NativeModelConfig` (the three per-tier blocks `high`/`mid`/`low`, each `Option<NativeTierConfig>`); `NativeTierConfig` (per-tier `{endpoint: Option<String>, model: Option<String>}` — auth intentionally absent from this struct, by spec); `TierConfig` (owned resolved view — `endpoint`, `model`, `key: Option<String>` — the key comes from the per-tier env var via `std::env::var`, not the TOML); `HIGH_API_KEY_ENV` / `MID_API_KEY_ENV` / `LOW_API_KEY_ENV` exported as `pub const`s (named generically — no provider name — so any OpenAI-protocol endpoint can use them; pinned by `test_spec_auth_env_var_constants_have_generic_names`); `load_model_config()` (returns `ModelConfig::default()` silently on absent or unparseable TOML); `write_starter_template()` (skips when the file exists; writes the per-tier-block template, every slot commented out so the file is a no-op on first use); the `native_high()` / `native_mid()` / `native_low()` accessors resolve each tier via `resolve_tier()` (TOML-or-default for endpoint/model, env-var-only for auth — each tier resolves its auth independently)

### tend-write-restriction
Correctness property of backends' `ToolPolicy` enforcement: the write- and delete-permission check must evaluate equivalent filesystem paths identically. An absolute path, a relative path with `..` components, and a symlink-resolved variant all referring to the same file must produce the same permission outcome. Tend can write to and delete any file under `.tinker/goals/` recursively (including the `packaged-goals/` subdirectory); deletion is the inverse of writing within the same boundary, enabling the Merge and Retire structural operations.

- `src/native.rs` — `path_within()` (canonical-resolution permission check: `fs::canonicalize` on existing targets, parent-directory canonicalization for new files, pure `lexical_normalize()` fallback when the filesystem can't resolve)

### goal-storage
On-disk TOML format at `.tinker/goals/<id>.toml`: ancestor-directory merge (cwd-most wins on duplicate ids), malformed-file reporting without blocking siblings, transparent symlink following, `[[children]]` / `[[related]]` link shape. **Four-tier discovery model** (see also `binary-relative-tier-loading` for the population mechanism): `project-local` (cwd `.tinker/goals/`), `ancestor global` (any ancestor's `.tinker/goals/`), `packaged` (`<tinker_dir>/goals/packaged-goals/` — tinker-shipped defaults vendored at each tinker_dir), and `binary-relative-packaged` (`<binary>/../../.tinker/goals/packaged-goals/` populated by `build.rs` and `include_dir!`). Tier labels are reported in `GoalCollision.contributors` and consumed by the eager-start diagnostic and the runtime event log. Collision policy: cross-tier overlaps (same id at distinct tiers) are reported via the startup diagnostic; intra-tier duplicates (same id twice within one tier, including the file-based + embedded copy of one binary-relative-packaged goal) are silently deduped to the first occurrence — outside the cross-tier diagnostic's scope.

- `src/goal.rs` — `Goal` (fields include `kind: Option<String>` — `"feature"` or `"behavior"`, optional on legacy goals), `RelatedLink`, `ChildLink`, `GoalNode`, `GoalCollision` (`contributors: Vec<(String, PathBuf)>` whose tier label follows the four-tier set), `LoadResult`; `GOAL_SCHEMA_KEYS_ORDER` (single source of truth for schema key order used in prompts and parse-error correction); `discover_tinker_dirs()`, `load_all_goals()` (production wrapper — resolves `current_exe()` and passes `include_embedded=true` via `cfg(not(test))` so registry installs see packaged goals), `load_all_goals_with_exe(..., include_embedded: bool)` (the four-pass merge: regular tier1/2 over `tinker_dirs`, tinker_dir-packaged tier3, binary-relative-packaged on-disk tier4a, then binary-relative-packaged embedded tier4b; same-tier dedupe in `record_loaded_goal`; cross-tier collision reporting via `LoadResult.collisions`; the `include_embedded` flag is the test-mode opt-out — `cfg(test)` passes `false` so fixture-driven tests aren't drowned in 13 packaged-goal entries), `load_goals()`, `load_packaged_goals()`, `load_binary_relative_packaged_goals()`, `load_embedded_packaged_goals()` (parses embedded entries with a synthetic `embedded://packaged-goals/<file>` source_path — the `packaged-goals` path component keeps `App::is_packaged`'s classification predicate working unchanged), `binary_relative_packaged_dir(exe_path)` (resolves `<binary>/../../.tinker/goals/packaged-goals/` with safe short-path handling — bare `tinker` or single-component paths produce an empty `PathBuf` that the caller rejects), `tier_label(dir, tinker_dirs)` (cwd-most is `project-local`, later dirs are `ancestor global`), `PACKAGED_TIER` and `BINARY_RELATIVE_PACKAGED_TIER` const labels, `EMBEDDED_PACKAGED_GOALS: Dir = include_dir!("$CARGO_MANIFEST_DIR/.tinker/goals/packaged-goals")` (compile-time embed), `save_goal()`, `build_tree()`, `build_compact_index()` (emits `kind` in each compact index entry), `build_full_text_index()`. **4 new + 3 updated `test_spec_*` functions**: `test_spec_embedded_fallback_loads_when_no_other_tier_has_goal` (embedded fills in when no on-disk tier has a goal), `test_spec_embedded_fallback_loses_to_on_disk_binary_relative` (on-disk copy wins on duplicate ids because it loads first), `test_spec_embedded_fallback_synthetic_path_includes_packaged_goals_component` (synthetic path satisfies `App::is_packaged`'s predicate), `test_spec_load_all_goals_with_exe_include_embedded_false_skips_fallback` (the test-mode opt-out); the 3 existing `load_all_goals_with_exe` callsites were updated to pass the new `include_embedded` flag.

### binary-relative-tier-loading
Population mechanism for the binary-relative packaged tier: a `build.rs` copies source `.tinker/goals/packaged-goals/*.toml` to `<target>/.tinker/goals/packaged-goals/` so local builds and `cargo install --path .` see the on-disk copy; `src/goal.rs`'s `include_dir!` macro compiles the same source into the binary as a fallback so `cargo install tinker` from a package registry (where no build step runs) still finds packaged goals. Together they satisfy the eager-start invariant in every build mode. On-disk copy wins on duplicate ids over the embedded fallback (same-tier dedupe in `record_loaded_goal`). Owns the eager-start diagnostic's emitted text — the loader's spec (four-tier label set, precedence, silent-skip behavior) is `goal-storage`'s; the check-exists invariant is `goal-agents`'s.

- `build.rs` — build-time copy step: reads `CARGO_MANIFEST_DIR/.tinker/goals/packaged-goals/`, copies each `*.toml` to `<target_dir>/.tinker/goals/packaged-goals/` (target dir resolved by walking four parents up from `OUT_DIR`); emits `cargo:rerun-if-changed=.tinker/goals/packaged-goals` and `cargo:rerun-if-changed=build.rs` so Cargo tracks the source dir for rebuilds; panics loudly when the source dir is missing, unreadable, or empty (a deployment error worth surfacing at build time, not via a confusing runtime panic); emits a `binary-relative-tier-loading: copied N packaged-goals TOML files to …` info line so `cargo build -v` shows the population. Does NOT cover `cargo install tinker` from a registry — no build step runs there, so the loader falls through to the embedded fallback.
- `Cargo.toml` — `build = "build.rs"` directive + `include_dir = "0.7"` dependency (the crate providing the `include_dir!` macro that compiles the source dir into the binary).
- `src/goal.rs` — `EMBEDDED_PACKAGED_GOALS: Dir = include_dir!("$CARGO_MANIFEST_DIR/.tinker/goals/packaged-goals")` (compile-time embed of the same source `build.rs` reads — single source of truth); `load_embedded_packaged_goals()` (parses embedded entries with synthetic `embedded://packaged-goals/<file>` source_path; per-entry error reporting via `errors` vec, matching the on-disk pass; `App::is_packaged`'s existing "any path component is `packaged-goals`" predicate picks them up as packaged without requiring a coordinated change to `packaged-goals-style`'s render rule); the `include_embedded` parameter on `load_all_goals_with_exe` (production wrapper `load_all_goals` sets it `true` via `cfg(not(test))`, test mode sets `false` via `cfg(test)` for fixture isolation — see `goal-storage`'s entry for the four-pass merge details).
- `src/main.rs` — eager-start diagnostic rewrite (the `expect("tend goal not found…")` after `load_all_goals`): the panic text is a three-section form (what went wrong → where the missing tier was supposed to come from → how to fix it), distinguishing dev (`cargo build`) from registry install (`reinstall`) so the user doesn't run the wrong fix, and naming `.tinker/goals/packaged-goals/tend.toml` as the source. Also contains three `include_str!("../.tinker/goals/packaged-goals/<file>.toml")` test fixtures (tend.toml, rummage.toml, jog.toml) — test-time fixtures pinned to the source tree; the previous `../packaged-goals/...` paths were updated to the canonical `.tinker/goals/packaged-goals/...` location.

### tier-edit

Tier defaults are now kind-aware: behavior goals default to high tier, feature goals default to mid tier, and low tier is used only when explicitly set.
TUI tier-change interaction: `t` on a focused goal cycles its tier (absent/mid → high → low → absent/mid) and writes the updated `tier` field immediately to the goal's source TOML file; the goal-detail header's `[kind · tier]` tag reflects the new value at once.

- `src/main.rs` — `effective_goal_tier()` (single source of truth for kind-aware tier resolution: explicit tier wins, absent tier: behavior→high, feature/unknown→mid), `cycle_tier()` (three-value cycle logic), `KeyAction::CycleTier(goal_id)` variant, key-event dispatch (`t` in the goal-tree returns `CycleTier` for any goal with a `source_path`), and the `CycleTier` event-loop handler that mutates `app.goals` in-place, serializes via `toml::to_string_pretty()`, and writes via `fs.write()`
